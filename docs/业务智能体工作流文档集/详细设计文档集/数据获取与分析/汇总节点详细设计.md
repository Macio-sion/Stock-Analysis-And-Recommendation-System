# 汇总节点详细设计
## agent状态参数示例
### 标识参数
```python
    # 工作流标识
    workflow_id: str
    ts_code: str
```
字段	类型	业务含义	对后续节点/系统的作用
workflow_id	str	本次分析任务的唯一标识，如 "wf_20260831_001"	全局追踪：贯穿整个工作流，用于日志关联、状态查询、断点恢复
ts_code	str	Tushare标准股票代码，如 "000001.SZ"	业务主键：告知阶段二“正在分析哪只股票”，多头/空头/研究经理都依赖此字段定位标的
### 技术分析参数
```python
technical_report: Dict[str, Any]      # 来自TechnicalAgentState.technical_report
fundamental_report: Dict[str, Any]    # 来自FundamentalAgentState.fundamental_report
sentiment_report: Dict[str, Any]      # 来自SentimentAgentState.sentiment_report
```
字段	来源	内容示例	对后续节点/系统的作用
technical_report	技术分析师	{"score":72, "trend":"上涨", "summary":"均线多头排列...", "key_levels":{...}}	阶段二多空辩论的原始素材：多头从中提取“趋势向上”作为论据；空头从中提取“RSI超买”作为论据
fundamental_report	基本面分析师	{"score":68, "valuation_status":"低估", "summary":"ROE高于行业...", "strengths":[...], "risks":[...]}	阶段二多空辩论的原始素材：多头引用 strengths，空头引用 risks
sentiment_report	舆情分析师	{"score":65, "polarity":"积极", "summary":"舆情整体积极...", "key_events":[...], "risk_factors":[...]}	阶段二多空辩论的原始素材：多头引用 key_events 中的积极事件，空头引用 risk_factors.

```python
technical_score: float
fundamental_score: float
sentiment_score: float
```
字段	取值范围	业务含义	对后续节点/系统的作用
technical_score	0-100	技术面综合得分，反映价格/量能维度的看好程度	阶段三策略引擎的核心输入：与其他两个得分一起加权计算最终推荐得分
fundamental_score	0-100	基本面综合得分，反映公司价值维度的看好程度	阶段三策略引擎的核心输入：同上
sentiment_score	0-100	舆情综合得分，反映市场情绪维度的看好程度	阶段三策略引擎的核心输入：同上
### 汇总信息
```python
all_scores: Dict[str, float] = field(default_factory=dict)
# {"technical": 72, "fundamental": 68, "sentiment": 65}
```
字段	业务含义	对后续节点/系统的作用
all_scores	将三个得分汇总到一个字典中，便于统一访问	便捷性设计：阶段三策略引擎可以直接通过 all_scores["technical"] 访问，无需分别读取三个独立字段；也方便遍历和调试
### 执行汇总
```python
total_duration_ms: Optional[int] = None
stage_status: str = "completed"       # completed / partial_failed / failed
errors: List[str] = field(default_factory=list)
```
字段	业务含义	对后续节点/系统的作用
total_duration_ms	阶段一总耗时（三个Agent并行执行的最长时间 + 汇聚开销）	性能监控：帮助判断阶段一是否存在性能瓶颈（如舆情API是否特别慢导致整体延迟）
stage_status	阶段一的整体执行状态："completed"（全部成功）/ "partial_failed"（部分失败，有降级数据）/ "failed"（完全失败）	流程控制：阶段二可根据此状态决定如何执行——若 "failed" 则直接终止；若 "partial_failed" 则在报告中标注“数据不完整”
errors	错误列表，如 ["舆情API调用超时，使用缓存数据"]	可观测性：让下游和运维人员了解阶段一执行过程中发生了什么异常，便于问题定位和报告标注
