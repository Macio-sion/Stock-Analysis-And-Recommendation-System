# 代码生成与沙箱执行引擎详细设计

## 数据源示例
### 算法描述输入
```text
用户描述：根据基本面、技术面、舆情面得分加权计算综合评分，
基本面权重 60%、技术 30%、舆情 10%，评分 >= 70 推荐买入，
40-69 观望，< 40 回避。
```
### 综合分析报告输入（作为算法上下文）
```python
comprehensive_report = {
    "rating": "看多",
    "comprehensive_score": 72,
    "score_breakdown": {"technical": 72, "fundamental": 68, "sentiment": 65, "debate_adjust": 5},
    "core_drivers": ["ROE高于行业"],
    "main_risks": ["资产负债率偏高"]
}
```
### 生成的 Python 代码示例
```python
def recommend(technical_score, fundamental_score, sentiment_score):
    score = fundamental_score * 0.6 + technical_score * 0.3 + sentiment_score * 0.1
    if score >= 70:
        action = "买入"
    elif score >= 40:
        action = "持有/观望"
    else:
        action = "回避"
    return {"action": action, "score": round(score, 2)}
```

## 结构化输出structure output详细
```python
# ============================================================
# 子模型：算法输入定义
# ============================================================
class AlgorithmInput(BaseModel):
    """自定义算法的一个输入参数定义"""
    name: str = Field(description="输入参数名，如 technical_score")
    type: str = Field(description="参数类型，如 float")
    description: str = Field(description="参数含义说明")
# ============================================================
# 子模型：算法输出定义
# ============================================================
class AlgorithmOutput(BaseModel):
    """自定义算法的一个输出定义"""
    name: str = Field(description="输出字段名，如 action")
    type: str = Field(description="输出类型")
    description: str = Field(description="输出含义说明")
# ============================================================
# 主模型：生成代码
# ============================================================
class GeneratedCode(BaseModel):
    """LLM 生成的推荐算法代码结构"""
    code: str = Field(
        min_length=10,
        description="完整的可执行 Python 代码"
    )
    language: str = Field(
        default="python",
        description="代码语言，固定为 python"
    )
    entry_point: str = Field(
        description="入口函数名，如 recommend"
    )
    dependencies: List[str] = Field(
        default_factory=list,
        description="第三方依赖列表，如 ['numpy']"
    )
    description: str = Field(
        description="对生成算法的简要说明"
    )
    inputs: List[AlgorithmInput] = Field(
        default_factory=list,
        description="算法的输入参数定义"
    )
    outputs: List[AlgorithmOutput] = Field(
        default_factory=list,
        description="算法的输出定义"
    )
```
上述仅供参考，实际实现中可能需要根据具体需求进行调整。
## agent状态参数解析
### 输入参数
```python
workflow_id: str
ts_code: str
symbol: str
algorithm_description: str
comprehensive_report: Dict[str, Any] = field(default_factory=dict)
technical_score: float = 0.0
fundamental_score: float = 0.0
sentiment_score: float = 0.0
```
字段	类型	业务含义	对后续节点/系统的作用
workflow_id	str	工作流唯一标识	贯穿全流程，用于日志关联和状态查询
ts_code	str	Tushare标准股票代码	业务主键：唯一确定分析标的
symbol	str	用户友好的股票代码	用于最终展示
algorithm_description	str	用户的算法描述（自然语言/伪代码）	代码生成的核心输入
comprehensive_report	Dict	研究经理的综合分析报告	算法生成的上下文参考
technical_score / fundamental_score / sentiment_score	float	三维度得分	算法执行时的输入参数
### 代码生成阶段

```python

```
字段	业务含义	对后续节点/系统的作用

#### C3节点数据（AST静态校验）

字段	业务含义	对后续节点/系统的作用

## 沙箱执行器详细配置
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 隔离方式 | Docker 容器 | 每次执行创建独立容器，结束后销毁 |
| CPU 限制 | 1 核 | 防止算法占满 CPU |
| 内存限制 | 256 MB | 防止内存溢出 |
| 执行超时 | 30 s | 超时强制终止并记录错误 |
| 网络访问 | 禁用 | 防止外联与数据外泄 |
| 文件系统 | 只读 | 仅允许读入输入数据，禁止写宿主文件系统 |
| 镜像 | 预置 python:3.11-slim | 预装 numpy 等白名单依赖 |

## WebSocket 事件流设计
```python
# 事件消息结构
{
  "type": "log" | "metric" | "code" | "status",   # 事件类型
  "execution_id": "exec_20260831_001",
  "seq": 12,
  "payload": {...},                                 # 具体内容
  "timestamp": "2026-08-31T10:00:00Z"
}
```
- `code`：代码生成完成后推送完整代码，前端渲染代码视图。
- `log`：执行过程中逐条推送日志，前端滚动展示。
- `metric`：推送指标数据点，前端实时更新曲线图。
- `status`：推送管线状态变更（编译中/执行中/成功/失败）。
