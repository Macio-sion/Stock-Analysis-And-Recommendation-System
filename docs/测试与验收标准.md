# 测试与验收标准

## 验收标准

### 阶段一：数据获取与基础分析
| 功能 | 验收标准 |
|------|----------|
| 技术分析 | 给定 ts_code 与时间窗口，能返回技术分析报告（趋势/关键价位/技术评分），指标计算正确 |
| 基本面分析 | 返回基本面报告（估值状态/财务评分/核心指标），四维度评分合理 |
| 舆情分析 | 从 alphaAI 网站获取舆情数据并返回舆情报告（情绪/热度/关键事件） |
| 汇总节点 | 三份报告与三维度得分正确汇聚为 StageOneMergeState |

### 阶段二：信息综合与辩论
| 功能 | 验收标准 |
|------|----------|
| 多头研究员 | 输出多头观点报告，支持论据 ≥3 条且含来源/权重/引用，置信度分解完整 |
| 空头研究员 | 输出空头观点报告，看跌论据充分且客观呈现正面因素 |
| 研究经理 | 输出综合分析报告，含共识/分歧裁决、综合评分与评级，评分可解释 |

### 阶段三：策略执行与推荐生成
| 功能 | 验收标准 |
|------|----------|
| 默认管线 | 按策略权重计算得分，正确映射阈值到买入/持有/回避 |
| 自定义算法（LLM 生成） | 自然语言描述能生成可执行 Python 代码并通过 AST 校验 |
| 自定义算法（沙箱执行） | 代码在隔离容器内执行，输出 action/score，超时/资源受限正常终止 |

### 安全
| 场景 | 验收标准 |
|------|----------|
| 危险代码拦截 | 含 os/subprocess/socket 等代码被 AST 拦截，不进入沙箱 |
| 沙箱逃逸防护 | 执行尝试网络访问/写宿主文件被拒绝 |
| 资源滥用 | 死循环/内存溢出在 30s 超时或 256MB 限制内被终止 |

## 测试用例（关键）
| 用例 | 前置 | 步骤 | 预期 |
|------|------|------|------|
| 完整推荐流程 | 有效 ts_code | 提交任务 | 三阶段依次完成，返回推荐结果 |
| 自定义权重 | strategy_type=自定义 | 权重和=1 | 按自定义权重计算得分 |
| 权重和≠1 | strategy_type=自定义 | 权重和=0.5 | 返回 400 参数错误 |
| LLM 生成代码 | 算法描述 | 提交描述 | 生成合法代码并通过校验 |
| 危险代码拦截 | 描述含 import os | 提交描述 | 返回 422，拦截提示 |
| 执行超时 | 算法含死循环 | 执行 | 30s 后强制终止，返回 504 |
| 断点恢复 | 阶段二失败 | 重跑 | 复用阶段一快照，从阶段二继续 |
| WebSocket 推送 | 执行自定义算法 | 订阅 workflow_id | 实时收到 code/log/metric/status 事件 |

## 测试分层
- 单元测试：技术指标计算、AST 校验、评分/推荐逻辑（`tests/test_agents/`）。
- 集成测试：三阶段完整链路（`tests/test_workflow/`）。
- 端到端测试：前端提交 → 后端执行 → 可视化展示。
