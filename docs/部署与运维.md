# 部署与运维

## 组件清单
| 组件 | 用途 | 部署方式 |
|------|------|----------|
| 应用服务 | FastAPI + Streamlit | Docker 容器 |
| PostgreSQL | 持久化存储 | Docker 容器 |
| Redis | 缓存 | Docker 容器 |
| Docker 沙箱 | 用户算法隔离执行 | 宿主机 Docker |

## docker-compose 编排（示意）
```yaml
services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: stock_recommendation
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  redis:
    image: redis:7
    ports:
      - "6379:6379"

  app:
    build: .
    environment:
      DATABASE_URL: postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/stock_recommendation
      REDIS_URL: redis://redis:6379
      TUSHARE_TOKEN: ${TUSHARE_TOKEN}
      LLM_MODEL: ${LLM_MODEL}
    depends_on:
      - postgres
      - redis
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock   # 沙箱执行器调用 Docker
    ports:
      - "8501:8501"

  worker:
    build: .
    command: python -m src.worker   # 任务队列消费者
    environment:
      DATABASE_URL: postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/stock_recommendation
      REDIS_URL: redis://redis:6379
      TUSHARE_TOKEN: ${TUSHARE_TOKEN}
      LLM_MODEL: ${LLM_MODEL}
      WORKER_CONCURRENCY: 2          # 单 Worker 并发任务数
    depends_on:
      - postgres
      - redis
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    deploy:
      replicas: 2                    # Worker 横向扩展

volumes:
  pgdata:
```

## 环境变量
| 变量 | 说明 |
|------|------|
| `DATABASE_URL` | PostgreSQL 连接串 |
| `REDIS_URL` | Redis 连接串 |
| `TUSHARE_TOKEN` | Tushare API 密钥 |
| `LLM_MODEL` | LLM 模型名（Ollama/OpenAI） |
| `SANDBOX_CPU_LIMIT` | 沙箱 CPU 限制（默认 1 核） |
| `SANDBOX_MEM_LIMIT` | 沙箱内存限制（默认 256MB） |
| `SANDBOX_TIMEOUT` | 沙箱执行超时（默认 30s） |

## 数据库初始化
- 首次启动执行 `scripts/init_db.py`，创建 7 张表及索引（见持久化设计文档）。

## 监控
| 指标 | 说明 |
|------|------|
| 工作流成功率 | completed / 总数 |
| 阶段耗时 | 各 agent 执行耗时（execution_duration_ms） |
| LLM token 消耗 | 各 ReAct agent 的 total_tokens_used |
| 沙箱执行失败率 | algorithm_executions 中 failed 占比 |
| 沙箱资源使用 | CPU/内存/超时告警 |

## 告警
| 事件 | 级别 | 处理 |
|------|------|------|
| 数据库连接失败 | P0 | 立即告警，触发故障排查 |
| 沙箱执行超时/资源耗尽 | P1 | 告警并记录，提示用户 |
| LLM 输出解析失败率过高 | P1 | 告警，检查提示词与模型 |
| 工作流失败率超阈值 | P2 | 告警，分析错误分布 |

## 日志采集
- 应用日志：loguru 输出，见「日志与系统配置.md」。
- 工作流日志：按 workflow_id 关联，落库 execution_logs 与文件。
- 建议接入日志聚合（如 ELK / Loki）实现集中检索与告警。
