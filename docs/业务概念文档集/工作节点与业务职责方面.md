# 工作节点与业务职责方面

## 概述
系统采用「三阶段工作流」编排，各阶段由若干工作节点协作完成。每个工作节点承担单一、明确的业务职责。新增的「自定义算法在线执行」能力以独立管线插入第三阶段，与默认硬编码管线并存。

## 节点总体划分
| 阶段 | 管线 | 节点 | 编排方式 |
|------|------|------|----------|
| 阶段一 | 数据获取与基础分析 | 技术分析师、基本面分析师、舆情分析师、汇总节点 | 硬编码 |
| 阶段二 | 信息综合与辩论 | 多头研究员、空头研究员、研究经理 | ReAct |
| 阶段三 | 默认推荐管线 | 策略匹配引擎、评分计算器、推荐决策器 | 硬编码 |
| 阶段三 | 自定义算法管线 | 算法解析、代码生成、AST 校验、容器创建、编译、执行、日志/指标采集 | LLM 生成 + Docker 沙箱 |
| 横切 | 实时可视化 | 代码视图、执行日志、分析曲线图 | WebSocket 推送 |

## 阶段一：数据获取与基础分析

| 节点 | 业务职责 |
|------|----------|
| 技术分析师 | 获取 OHLCV 行情数据，计算趋势/动量/波动率/成交量指标，判断趋势方向，生成技术分析报告与评分 |
| 基本面分析师 | 获取财务与估值数据，从盈利能力/成长能力/财务健康/估值四维度评分，生成基本面分析报告与评分 |
| 舆情分析师 | 采集新闻/社交媒体/研报数据，进行 NLP 分析与情绪量化，生成舆情分析报告与评分 |
| 汇总节点 | 汇聚三份报告与三维度得分，形成 `StageOneMergeState`，作为阶段二输入 |

## 阶段二：信息综合与辩论

| 节点 | 业务职责 |
|------|----------|
| 多头研究员 | 从三份报告提取看涨论据，构建看涨逻辑链，输出多头观点报告与置信度 |
| 空头研究员 | 从三份报告提取看跌论据，构建看跌逻辑链，输出空头观点报告与置信度 |
| 研究经理 | 对比多空观点，识别共识与分歧，对分歧点裁决，输出综合评分、评级与综合分析报告 |

## 阶段三：默认推荐管线

| 节点 | 业务职责 |
|------|----------|
| 策略匹配引擎 | 识别策略类型（价值/成长/技术/情绪/均衡/自定义权重），加载各维度权重 |
| 评分计算器 | 按权重计算加权综合得分，计算置信区间并对比历史基准 |
| 推荐决策器 | 依据得分阈值输出买入/持有/回避等推荐动作，并构建推荐理由 |

## 阶段三：自定义算法管线（新增）

| 节点 | 业务职责 |
|------|----------|
| 算法描述解析 | 接收用户自然语言或伪代码描述，解析出算法意图、输入输出与计算逻辑 |
| 代码生成 | 调用 LLM 将算法描述转换为可执行的 Python 推荐算法代码 |
| AST 静态校验 | 对生成代码做抽象语法树静态校验，拦截危险调用与非法语法 |
| 容器创建 | 在 Docker 沙箱中创建隔离运行环境，施加资源限制（CPU/内存/网络/超时） |
| 代码编译 | 对 Python 代码进行语法编译校验，产出编译结果 |
| 沙箱执行 | 在隔离容器内执行自定义算法，产出推荐结果 |
| 日志/指标采集 | 采集执行过程中的日志流与指标时间序列，供可视化与持久化 |

## 横切：实时可视化（新增）

| 节点 | 业务职责 |
|------|----------|
| 代码生成视图 | 实时展示 LLM 生成的代码片段 |
| 执行日志视图 | 通过 WebSocket 实时滚动展示编译与执行日志 |
| 分析曲线图 | 基于指标时间序列实时绘制曲线（收益率、评分、回撤等） |
