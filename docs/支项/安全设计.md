# 安全设计

## 安全目标与范围
本系统的核心安全风险来自「用户自定义推荐算法在线生成与执行」，其次是金融数据与密钥管理。安全设计遵循最小权限、纵深防御、可审计三原则。

## 代码执行安全（核心）

用户算法经 LLM 生成后，在 Docker 沙箱中执行。采用三层防护：

### 第一层：AST 静态校验
- 在代码进入沙箱前，用 Python `ast` 模块做静态校验。
- 拦截危险导入：`os`、`sys`、`subprocess`、`socket`、`requests`、`shutil`、`ctypes` 等。
- 拦截危险调用：`eval`、`exec`、`__import__`、`open`（写模式）、`compile`。
- 白名单依赖：仅允许 `numpy`、`pandas`、`math`、`statistics` 等计算类库。
- 校验失败则终止管线，错误信息反馈前端，不进入沙箱。

### 第二层：Docker 容器隔离
- 每次执行创建独立容器，执行结束后立即销毁。
- 使用最小权限镜像 `python:3.11-slim`，非 root 用户运行。
- 网络默认禁用（`--network none`），防止数据外泄与外联攻击。
- 文件系统只读（挂载只读卷），禁止写宿主文件系统。
- 禁用容器特权模式与宿主机资源挂载。

### 第三层：资源限制
| 资源 | 限制 | 说明 |
|------|------|------|
| CPU | 1 核 | 防止占满宿主机 CPU |
| 内存 | 256 MB | 防止内存耗尽 |
| 执行超时 | 30 s | 超时强制 kill 并记录 |
| 进程数 | 限制 | 防止 fork 炸弹 |
| 磁盘 | 只读 + 限额 | 禁止落盘 |

## 密钥与配置管理
- 所有密钥（Tushare token、数据库密码、LLM API key）通过环境变量注入，不硬编码、不入库、不入文档。
- 使用 `.env` 文件 + `.env.example` 模板，`.env` 加入 `.gitignore`。
- 配置中心统一管理，支持环境隔离（dev/test/prod）。

## 权限模型
- 用户需登录后使用系统（Streamlit 登录界面）。
- 「配置选项 → 修改系统参数」仅限管理员角色，普通用户只读。
- 自定义算法执行按用户配额限流，防止资源滥用。

## 数据安全
- 金融数据使用需遵循数据来源（Tushare）的授权与合规要求。
- 日志中对敏感字段（如 token、用户标识）脱敏后再输出。
- 数据库访问使用最小权限账号，禁止 root 直连。

## 网络安全
- WebSocket 连接需携带鉴权 token 校验，防止未授权订阅任务日志。
- REST API 与 WebSocket 均启用 HTTPS/WSS（生产环境）。

## 审计
- 记录自定义算法的生成、校验、执行全链路日志（execution_logs）。
- 记录所有配置变更与登录行为，支持事后追溯。
