# 错误处理与降级策略

## 错误分类
| 类别 | 典型场景 | 影响范围 |
|------|----------|----------|
| 数据源错误 | Tushare 超时/限流、舆情库无数据 | 阶段一某 agent 失败 |
| LLM 错误 | 生成超时、输出无法解析、token 超限 | 阶段二/代码生成失败 |
| 沙箱执行错误 | 编译失败、执行超时、资源耗尽 | 自定义算法管线失败 |
| 系统错误 | 数据库连接失败、容器创建失败 | 全局 |

## 阶段一：数据获取与基础分析
- **数据缺失降级**：某数据源失败时，对应 agent 标记 `partial_failed`，报告标注「数据不完整」，其余 agent 继续执行。
- **缓存兜底**：Tushare 调用失败时回退 Redis 缓存数据（若有）。
- **重试策略**：外部 API 调用失败重试 2 次（指数退避），仍失败则降级。

## 阶段二：信息综合与辩论
- **LLM 输出解析失败**：重试 1 次；仍失败则用 `output_parser` 的兜底默认结构。
- **轮次超限**：ReAct 达到 `max_rounds` 强制停止，基于已有论据输出报告，`exit_reason=max_rounds`。
- **单边失败**：多头/空头某一方失败时，研究经理仅基于成功方报告裁决，并标注「辩论不完整」。

## 阶段三：策略执行与自定义算法
- **策略配置非法**：权重和不为 1 时，返回 400，提示用户修正。
- **AST 校验失败**：返回 422，错误信息（危险模块/语法错误）反馈前端，不进入沙箱。
- **编译失败**：记录 `compile_result` 与错误日志，状态标记 `failed`。
- **执行超时/资源耗尽**：沙箱强制终止，状态 `failed`，返回 504 / 资源错误。
- **容器创建失败**：重试 1 次，仍失败则整体 `failed`。

## 全局状态语义
| 状态 | 含义 | 处理 |
|------|------|------|
| `completed` | 全阶段成功 | 正常返回结果 |
| `partial_failed` | 部分降级但有可用数据 | 返回结果并附「数据不完整」提示 |
| `failed` | 关键步骤失败 | 记录 error_message，返回 500/422/504 |

## 错误码
统一使用 [API 接口设计](API接口设计.md) 中定义的错误码（400/401/403/404/409/422/429/500/504）。

## 可观测性
- 所有错误写入 `workflow_instances.error_message` 与 `execution_logs`。
- 关键错误（沙箱执行失败、数据库异常）触发告警（见部署与运维文档）。
